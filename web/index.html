Recommended Safe Next Steps:

    Suspicious links are not always obvious.

    Phishing campaigns exploit human cognitive biases and interface limitations. Modern web browsers often collapse or truncate URLs on mobile screens, making subtle tricks—such as user-authentication syntax (@), multiple confusing subdomains, or lookalike internationalized characters (Punycode)—exceptionally effective.

    PhishGuard dissects the structural syntax of candidate web addresses to illustrate how threat actors construct deceptive links. By understanding the mechanical anatomy of a link, users and security analysts can identify anomalies without needing risky manual interactions.

    EDUCATIONAL METHODOLOGY

    The 6 Detection Heuristics

    Detailed technical explanation of the structural checks specified in the EWB Cybersecurity Mini Project Workbook.

    IMPORTANT EDUCATIONAL BOUNDARY:
    "No listed warning signs" does NOT mean a URL is safe. Sophisticated phishing campaigns routinely register new domains, configure valid SSL/TLS certificates, and avoid structural anomalies. This system evaluates static syntax for education, not real-time reputation.
    CHECK 01 // STRUCTURE AGENT

    Presence of '@' Symbol

    Why it matters: In URI RFC 3986 syntax, the @ character separates user credentials from the actual destination host. Attackers construct URLs like http://trustedbank.com@malicious-host.invalid/ to trick users who only read the left part of the address.

    Fictional Example: http://account.paypal.com@verify-login.invalid/

    Limitations: Legitimate web applications occasionally use @ in URLs (e.g. webmail mailto handlers or API authentication strings).

    CHECK 02 // STRUCTURE AGENT

    URL Length Exceeding 100 Characters

    Why it matters: Extremely long URLs often push the true destination or suspicious file extensions beyond the visible address bar on mobile devices or email clients.

    Fictional Example: https://example.com/security/login/verification/session/user/auth/token/redirect/data/session-id-9817293817293817293817293817293871928371928371928371928371928371298371928371928371928371928371

    Limitations: Many legitimate cloud services, search queries, and OAuth 2.0 flows produce URLs longer than 100 characters.

    CHECK 03 // HOSTNAME INTELLIGENCE AGENT

    Direct IPv4 Address Hostname

    Why it matters: Legitimate businesses operate under registered domain names. Threat actors sometimes use raw IP addresses to bypass domain-based threat intelligence lists and conceal organizational ownership.

    Fictional Example: http://192.0.2.10/account/login

    Limitations: Direct IP addresses are standard for local networking (192.168.x.x, 10.x.x.x), IoT hardware, and temporary server administration.

    CHECK 04 // HOSTNAME INTELLIGENCE AGENT

    Multiple Hostname Segments (≥ 5 Labels)

    Why it matters: Attackers chain multiple subdomains to emulate trusted domain structures (e.g. paypal.com.customer-support.verify.attacker.invalid) where the true base domain is at the very end.

    Fictional Example: https://a.b.c.d.e.example.invalid/path

    Limitations: Enterprise multi-region cloud services (e.g., AWS S3 bucket endpoints or Microsoft Azure services) legitimately use 5 or more segments.

    CHECK 05 // HOSTNAME INTELLIGENCE AGENT

    Punycode Hostname Encoding ('xn--')

    Why it matters: Punycode allows Internationalized Domain Names (IDNs) in ASCII. Attackers use homograph attacks—substituting lookalike characters from Cyrillic or Greek alphabets for Latin letters—to impersonate genuine brands.

    Fictional Example: https://xn--example.invalid/

    Limitations: Punycode is an essential international web standard enabling non-Latin languages for millions of users worldwide.

    CHECK 06 // PROTOCOL ANALYSIS AGENT

    Unencrypted HTTP Scheme

    Why it matters: Plain HTTP lacks transport encryption. Sensitive data, login credentials, and session cookies are transmitted in cleartext, making them vulnerable to network interception.

    Fictional Example: http://bank-portal.invalid/login

    Limitations: Most modern phishing websites now use valid HTTPS certificates. The presence of HTTPS alone does NOT prove a website is trustworthy.
